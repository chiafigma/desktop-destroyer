# Attribution and provenance

This is an unofficial fan port. **None of the artwork or audio in this repository is
ours.** This file records where each piece came from, so that nobody has to guess later.

## The original

**Desktop Destroyer** — the 1990s freeware stress-reliever, also circulated as Desktop
Games, Stress Reducer, Stress Relief, The Stress Game and Desktop Killer.

- **Original design:** Miroslav Němeček
- **Source:** <http://www.gemtree.com/program.htm>

## The rip we actually use

The sprites and sounds in this repo are not taken from the original executable. They come
from the [windows93.net](https://windows93.net) recreation:

- **Sprite ripping:** Jankenpopp & Zombectro
- **Recreation code:** Zombectro
- **Asset origin:** `https://windows93.net/c/programs/misc/DesktopDestroyer/assets`

`scripts/fetch-w93-assets.mjs` is what pulled them down, walking the naming scheme file by
file. It's idempotent, so it can refill `ref/w93/` if the directory is ever lost.

> Why fetch file-by-file rather than download the folder: windows93's folder export
> serializes directory metadata only, so downloading `0-hammer/` yields a 1024-byte tar of
> zeros. Ten of those empty tars sat in the repo root for a while as a souvenir of finding
> that out; they have been deleted.

No licence accompanies any of this material. The original is freeware; the rip carries no
stated terms.

## What's vendored, directory by directory

| Path | What it is | In the build? |
| --- | --- | --- |
| `ref/w93/` | The windows93 rip, one directory per weapon — 107 PNG and OGG files. **This is the canonical set.** | **Yes** — every sprite and sound is inlined from here |
| `ref/windows93/` | An earlier copy of the same rip, 104 files. 102 of them are byte-identical to `ref/w93/`. | No |
| `ref/sprites/`, `ref/sounds/` | An older rip with `.webm` audio, from a different third-party web reimplementation. Superseded. | No — see [assets.md](assets.md#what-happened-to-sheets-and-sounds) |
| `ref/src/` | Weapon and sprite configs in TypeScript from that same earlier reimplementation. Reference only. | No |
| `desktop-destroyer-ref/` | The windows93 app itself — `DesktopDestroyer.js`, `script.js`, `index.html`, `about.md`. This is the authority for upstream weapon tuning, and the weapon files in `src/shared/weapons/` cite it by name. | No |
| `assets/icons-src/`, `assets/icons/`, `assets/cursors/` | Menu icons. **Ours**, generated by `npm run assets`. | `assets/icons/` only |
| `cover.png` | Plugin cover art. Ours. | No |

Two notes on the duplication, for whoever cleans up next:

- `ref/windows93/` is redundant with `ref/w93/` and could go, with one caveat: it holds
  `2-machine-gun/press.png` and `4-color-thrower/press.png`, which `ref/w93/` does not.
  `ref/w93/` has five sounds it lacks in return.
- `ref/sprites/`, `ref/sounds/` and `ref/src/` are kept deliberately, as a record of the
  earlier approach and its upstream configs, not because anything reads them.

## Sharing this repo

This repository is **internal**. It carries no `LICENSE`, deliberately: we can't license
work that isn't ours to license, and the vendored assets have no stated terms.

That's fine for an internal MakerWeek project. It is the thing to resolve before this goes
anywhere public, because publishing the repo as it stands would redistribute someone
else's artwork and audio. If that comes up, the options are roughly:

1. **Stop committing the art.** Gitignore `ref/w93/` and let `scripts/fetch-w93-assets.mjs`
   fetch it at setup, so the assets are never in our distribution. The repo then depends on
   windows93.net staying up.
2. **Ask.** Miroslav Němeček's site lists contact details, and the rippers are credited
   above.
3. **Redraw the art.** The port's structure doesn't depend on these specific PNGs — the
   sprite geometry is declared per weapon and verified against whatever files are on disk.

Until one of those happens, keep it internal and keep the credits intact.
